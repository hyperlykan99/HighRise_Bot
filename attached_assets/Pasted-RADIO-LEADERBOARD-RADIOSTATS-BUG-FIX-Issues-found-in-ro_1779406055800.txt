RADIO LEADERBOARD / RADIOSTATS BUG FIX

Issues found in room testing:

1. !radiostats produced no DJ_DUDU reply.
2. !toplisteners produced no DJ_DUDU reply.
3. !topdisliked produced no DJ_DUDU reply.
4. !radiohelp advertises !save, but the real favorite command should be !fav / !favorite.
5. !topsongs appears to show liked songs instead of most requested/played songs.
6. Leaderboard command meanings need to be clear and consistent.

Do not rewrite radio backend.
Do not change playback/AzuraCast/SFTP logic.
Do not touch emote system.

Inspect:
- modules/radio_commands.py
- modules/help_cmds.py
- modules/multi_bot.py
- database.py
- any radio stats/reward tables added
- command routing/ownership maps

==================================================
1. FIX COMMAND ROUTING / HANDLERS
==================================================

Make sure these commands are registered, routed, and handled by DJ_DUDU only:

!radiostats
!toplisteners
!toprequests
!topsongs
!topliked
!topdisliked

Other bots must stay silent.

If a command has no data yet, it should still reply with a helpful empty state.

Examples:
📊 No radio stats yet.
🎧 No listener data yet.
👎 No disliked songs yet.

Do not silently fail.

==================================================
2. FIX RADIOHELP FAVORITE COMMAND
==================================================

In !radiohelp / !djhelp / !commands radio:

Replace:
!save — Save current song

With:
!fav — Save current song

Also mention:
!favorite — Save current song
!favorites — View saved songs

Do not advertise !save unless it actually exists and works.

==================================================
3. DEFINE LEADERBOARD MEANINGS
==================================================

Use these meanings:

!toplisteners
= users with highest radio_points/activity

!toprequests
= users with most successful song requests

!topsongs
= songs with most requests/plays

!topliked
= songs with most likes

!topdisliked
= songs with most dislikes

Do not mix these together.
