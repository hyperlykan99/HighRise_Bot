==================================================
1. CONNECT RADIOSTATS TO REAL EXISTING DATA
==================================================

!radiostats should not rely only on a new empty radio_user_stats row.

If radio_user_stats exists but has no data, aggregate from existing real tables:

Requests:
- successful completed/queued/played requests from request_queue / yt_request_jobs / radio request tables
- count only successful requests by this user

Likes:
- count rows in dj_ratings where user_id = current user and rating='like'

Dislikes:
- count rows in dj_ratings where user_id = current user and rating='dislike'

Favorites:
- count rows in dj_favorites where user_id = current user

Playlists:
- count playlists owned by user in radio playlist table

Playlist songs:
- count playlist songs added by user if tracked

Playlist plays:
- count playlist plays if tracked

Points:
- use radio_user_stats.radio_points if available
- if missing, calculate safe estimate:
  requests*5 + likes*1 + dislikes*1 + favorites*2 + playlists*3

Expected:
If user has favorites/ratings/playlists but no radio_user_stats row yet, !radiostats must still show those counts.

==================================================
2. ADD HOOKS FOR FUTURE STATS
==================================================

Make sure successful actions update radio_user_stats:

!play successful queue:
- increment requests_count
- add radio_points

!like:
- increment likes_count only for first rating on that song
- do not reward repeated same like

!dislike:
- increment dislikes_count only for first rating on that song
- do not reward repeated same dislike

!fav / !favorite:
- increment favorites_count only when newly added

!playlist create:
- increment playlists_created only when new playlist created

!playlist add / addcurrent:
- increment playlist_songs_added only when non-duplicate song is added

!playlist play:
- increment playlist_plays only when at least one song queues successfully

Do not increment for:
- failed request
- duplicate favorite
- duplicate playlist song
- command that only displays a list
- like/dislike toggle farming

==================================================

!radiostats output should combine:
- stored stats from radio_user_stats

Use max(stored_count, live_count) when appropriate so old activity shows up.

Example:
