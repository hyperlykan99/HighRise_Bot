- startup
- reconnect/watchdog
- respawn
- room join
- Highrise token handling
- unrelated game modules
- multi-bot lifecycle

Only BOT_MODE=dj / DJ_DUDU handles radio commands.

GOAL:
Make DJ_DUDU the single queue authority.
AzuraCast should only stream/output audio.

Fix these current bugs:
1. NOW PLAYING song still appears in !q / UP NEXT.

8. Requests are sometimes mislabeled as AutoDJ.

PART 3 — REQUEST DETECTION
━━━━━━━━━━━━━━━━━━━━

When reading AzuraCast Now Playing, match request in this order:

1. media_id / song_id
2. AzuraCast unique_id
3. file path starts with Requests/
4. filename
5. youtube_id stored in DB
6. normalized/fuzzy title match only as last fallback

Important:
If now_playing path or filename is from Requests/, treat it as REQUEST, not AutoDJ.

Do NOT rely on title-only matching because AzuraCast metadata may be long, trimmed, changed, or different from YouTube title.

When a request is matched:
- status = playing
- started_at = now
- playing_media_id = matched media_id if available
- playing_unique_id = matched unique_id if available
- remove it from !q / UP NEXT immediately

PART 5 — IMMEDIATE REQUEST TAKEOVER WITHOUT RESTART BUG
━━━━━━━━━━━━━━━━━━━━

Problem:
Request appears in Requests playlist, but AutoDJ continues OR current song restarts when new request is added.

Rules:
- Adding a request to queue must NOT restart current song.
- Do not restart Liquidsoap/station just because a request was added.
- Do not reload whole station on enqueue.
- Do not call skip until request is verified and intended to take over.

After request is promoted and playlist_verify succeeds:
1. Call AzuraCast backend skip:
   POST /api/station/{station_id}/backend/skip

2. Treat HTTP 200 or 204 as success.

3. Poll Now Playing every 1 second for 15 seconds.

4. If nowplaying is not requested media after 5 seconds:
   call backend skip one more time.

5. If still not requested after 15 seconds:
   keep request queued silently or say compactly:
   🎵 Added to UP NEXT.

Do not say “playing next” unless it is actually next.

PART 7 — PLAYED/SKIPPED CLEANUP
━━━━━━━━━━━━━━━━━━━━

When request leaves Now Playing:
1. Mark DB row:
   status = played
   played_at = now

If skipped:
   status = skipped
   played_at = now

2. Cleanup/move file:
From:
Requests/<filename>.mp3

To:
PlayedRequests/<filename>.mp3

If move is unavailable:
- copy to PlayedRequests
- delete from Requests

3. Remove media from Requests playlist relation if API supports it.

4. Rescan/import AzuraCast media.

5. Verify:
- file no longer exists in Requests/
- media no longer active in Requests playlist
- !q does not show it

Never delete or move:
- Chill
- default
- Party Remixes
- DJ sets
- any file not in DJ_DUDU request DB

Only cleanup files:
- path starts with Requests/
- tracked in request DB
- uploaded/promoted by DJ_DUDU

Cleanup must be idempotent:
- already moved = success
- already deleted = success
- not in playlist = success
- already marked played/skipped = do nothing

PART 8 — FIX REQUESTS FOLDER VS PLAYLIST DESYNC
━━━━━━━━━━━━━━━━━━━━

Current issue:
Requests media folder count and Requests playlist count do not match.
Example:
Requests folder has 2 files, playlist shows 4 songs.

Required:
Create reconciliation function:
reconcile_requests_playlist()

It should:
1. List active files in Requests/.
2. List media assigned to Requests playlist.
3. For each playlist item:
   - if file is missing from Requests/
   - OR DB status is played/skipped/failed/cancelled
   - OR media is not tracked by DJ_DUDU
   then remove it from Requests playlist.

4. For each active DB pending/queued request:
   - ensure file exists in Requests/
   - ensure media assigned to Requests playlist.

5. Run reconciliation:
   - after upload/promote
   - after cleanup
   - on bot startup if safe
   - when admin uses cleanup command

Do not restart station during reconciliation.
