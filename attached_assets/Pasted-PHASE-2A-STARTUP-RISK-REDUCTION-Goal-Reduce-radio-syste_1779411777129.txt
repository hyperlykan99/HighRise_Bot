PHASE 2A — STARTUP RISK REDUCTION

Goal:
Reduce radio system startup/crash risk before any module migration.

This phase is safety/stability only.
Do NOT add features.
Do NOT move modules yet.
Do NOT change command behavior.
Do NOT touch emote system.
Do NOT change playback logic itself.

Main findings from audit:
- playback_engine.py self-starts poll loop on import
- heavy radio modules imported globally by all bots
- yt_request.py loads yt_dlp/paramiko globally
- non-DJ bots may load DJ radio systems unnecessarily

==================================================
1. FIX PLAYBACK_ENGINE AUTO-START
==================================================

Current issue:
playback_engine.py starts polling loops on import.

This is dangerous because:
- importing module can start background tasks
- non-DJ bots may accidentally start radio pollers
- import failures can affect all bots

Fix:
- remove auto-start behavior from import side-effects
- create explicit startup function:
  start_playback_engine(bot)

Requirements:
- poll loop starts ONLY when explicitly called
- no polling loop starts during module import
- importing playback_engine.py must be safe

==================================================
2. DJ-ONLY STARTUP GUARDS
==================================================

Ensure ONLY DJ_DUDU / BOT_MODE=dj starts:
- playback engine
- AzuraCast polling
- yt cleanup tasks
- radio startup tasks
- vibe monitoring
- now-playing polling
- verified skip tasks

Use existing:
should_this_bot_run_module("yt_request")

or BOT_MODE=dj checks consistently.

3. REDUCE GLOBAL IMPORT RISK
