# ChillTopia Owner/Staff Dashboard

Secure sidecar web dashboard for the HighRise multi-bot project.

The dashboard does not edit bot source files. It uses this flow:

```text
Browser UI -> Express API -> shared SQLite database -> bot modules read settings
```

Existing bot behavior stays intact until a bot module intentionally reads a new
dashboard setting from `bot_settings` or `module_flags`.

## Features

- Owner/staff login with PBKDF2 password hashing
- HttpOnly session cookie auth
- CSRF token checks for authenticated write APIs
- Lightweight in-memory rate limiting and security headers
- Role and permission flags:
  - `manage_radio`
  - `manage_casino`
  - `manage_games`
  - `manage_titles`
  - `manage_staff`
  - `view_logs`
  - `emergency_controls`
- Staff and bot-role management
- Settings and module-flag management
- Radio view with now playing, queue, remove request, clear queue, skip-request flag
- Casino/game setting editor surface
- Title catalog and assignment surface
- Bot live tracker using existing `bot_instances`
- Audit logs for every dashboard write
- Emergency controls that write DB flags only

## Admin Panel Pages

The owner/staff browser UI has its own source files in `dashboard/admin-ui/`.
`npm run build` copies those files into `dashboard/public/`, and `npm start`
serves `dashboard/public/` through `server.mjs`.

This dashboard does not use `artifacts/dj-status` or the DJ DUDU status UI.

The browser UI polls the backend every few seconds on live pages. It includes:

- Overview
- Radio
- Casino
- Games
- Titles
- Staff
- Settings
- Live Tracker
- Logs
- Emergency

## Required Environment Variables

```env
PORT=3000
DB_PATH=/absolute/path/to/highrise_hangout.db
DASHBOARD_BOOTSTRAP_OWNER=YourOwnerUsername
DASHBOARD_BOOTSTRAP_PASSWORD=ChangeThisLongPassword
```

Optional:

```env
DASHBOARD_SESSION_DAYS=7
DASHBOARD_COOKIE_SECURE=1
REMOTE_STATUS_URL=https://your-replit-url/api/dj/status
AZURACAST_STREAM_URL=https://public-stream-url.example/radio.mp3
```

Do not put `BOT_TOKEN`, `AZURA_API_KEY`, room passwords, or other bot secrets in
frontend code. The dashboard never sends those values to the browser.

## First Owner Creation

The first owner can be created safely from environment variables:

```bash
export DB_PATH=/srv/highrise-bot/highrise_hangout.db
export DASHBOARD_BOOTSTRAP_OWNER=Marion
export DASHBOARD_BOOTSTRAP_PASSWORD='use-a-long-random-password'
npm start
```

On startup, `server.mjs` creates the owner only if that username does not
already exist. Remove the bootstrap password from the environment after the
first successful login.

## Run Locally

```bash
cd dashboard
npm install
npm run build
DB_PATH=/absolute/path/to/highrise_hangout.db npm start
```

Open:

```text
http://localhost:3000
```

Use the same SQLite file that the bots use. On production/VPS this usually
means setting `DB_PATH` to the same value as the bot process `SHARED_DB_PATH`.
If `DB_PATH` is omitted, the dashboard defaults to
`../artifacts/highrise-bot/highrise_hangout.db` from this directory.

## Build Structure

```text
dashboard/
  admin-ui/       # source files for the owner/staff admin dashboard
  public/         # generated by npm run build; served by npm start
  server.mjs      # Express APIs and static file serving
  build.sh        # copies admin-ui into public; never reads artifacts/dj-status
```

`npm run build` intentionally removes and recreates `dashboard/public/` from
`dashboard/admin-ui/` so old DJ status assets cannot remain the served UI.

## Bot Integration Notes

Current dashboard write surfaces are intentionally conservative. Bot runtime
code reads dashboard flags through `modules/dashboard_settings.py`; the web
server still writes database rows only and never edits source files.

Bot modules currently read:

- `module_flags.module='radio'` and `bot_settings.key='requests_enabled'`
  before accepting new radio requests.
- `module_flags.module='casino'` before accepting casino commands.
- `module_flags.module='games'` and `bot_settings.key='games.enabled'` before
  accepting optional game commands.

Planned/future bot reads:

- `bot_settings.key='radio.skip_requested'` if dashboard skip support is added.
- `bot_settings` keys beginning with
  `casino`, `bj_`, `rbj_`, `poker`, or `daily_` before accepting casino/game
  settings.

Emergency controls write flags only, except `clear_queue`, which marks upcoming
radio request rows `cancelled` in `yt_request_jobs`. It does not touch source
files or secrets.

## Deployment

VPS deployment steps:

```bash
cd /srv/HighRise_Bot
git pull --rebase origin main
cd dashboard
npm install
npm run build
cp .env.example .env   # first deploy only
nano .env
npm start
```

Minimum `.env`:

```env
PORT=3000
DB_PATH=/absolute/path/to/the/same/highrise_hangout.db/used/by/the/bots
DASHBOARD_BOOTSTRAP_OWNER=YourOwnerUsername
DASHBOARD_BOOTSTRAP_PASSWORD=UseALongTemporaryPassword
DASHBOARD_COOKIE_SECURE=1
```

After the first successful login, remove `DASHBOARD_BOOTSTRAP_PASSWORD` from
`.env` and restart the service.

To verify the VPS is serving the correct UI:

```bash
cd /srv/HighRise_Bot/dashboard
npm run build
grep -R "ChillTopia Admin" public/index.html public/app.js
grep -R "dj-status\\|DJ DUDU" public || true
npm start
```

The second `grep` should not find DJ status UI files in `dashboard/public/`.

Example systemd unit:

```ini
[Unit]
Description=ChillTopia Owner Dashboard
After=network.target

[Service]
Type=simple
User=chilltopia
WorkingDirectory=/srv/chilltopia-dashboard
EnvironmentFile=/srv/chilltopia-dashboard/.env
ExecStart=/usr/bin/node server.mjs
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Put nginx or another reverse proxy with HTTPS in front of the dashboard before
exposing it publicly.
